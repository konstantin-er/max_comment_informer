# Уведомления о комментариях MAX

Небольшой бот для самостоятельного запуска: сообщает администраторам о новых комментариях к постам каналов MAX. Уведомление показывает автора, канал, текст и кнопку перехода к посту. Через «Действия» можно удалить комментарий или включить автоудаление новых комментариев того же автора в этом канале.

## Запуск

1. Создайте бота в MAX и получите его токен.
2. Скопируйте `.env.example` в `.env`. Укажите `BOT_TOKEN` (секретный токен API) и `BOT_USERNAME` (ник бота без `@`, для ссылки в приветствии).
3. Запустите `docker compose up -d --build`.
4. Откройте бота в MAX и нажмите «Начать». Каждый администратор, которому нужны уведомления, делает это отдельно.
5. Включите комментарии в канале. Добавьте бота в канал и назначьте администратором с правами **читать все сообщения** (`read_all_messages`) и **удалять посты и комментарии** (`delete`).

Бот автоматически определяет каналы, где он назначен администратором. Отдельный список ID каналов в `.env` не нужен. Уведомления получают только действующие администраторы канала, которые начали диалог с ботом. Комментарии самих администраторов и владельца канала пропускаются: бот не уведомляет о них и не удаляет их автоматически. При удалении бота из канала новые уведомления по этому каналу прекратятся.

```bash
cp .env.example .env
# Заполните .env
docker compose up -d --build
docker compose logs -f bot
```

Состояние (курсор событий, получатели и локальные блокировки) хранится в Docker volume `bot_data`. Не запускайте две копии с одним токеном: они будут конкурировать за поток обновлений. Для остановки: `docker compose down`; volume при этом сохраняется.

## Что делают кнопки

- **Перейти** открывает пост. Для приватного канала MAX может не вернуть публичную ссылку на пост; тогда используется ссылка канала, а если её нет — кнопка не показывается.
- **Удалить** удаляет один комментарий через API MAX. Восстановить его нельзя.
- **Блокировать комментарии** удаляет текущий комментарий и заносит автора в локальный список. Следующие комментарии этого автора в данном канале бот удаляет после получения события. Это **не блокировка подписчика в MAX**: до обработки ботом комментарий может быть виден. Список хранится в volume; чтобы убрать запись, можно выполнить `DELETE FROM bans WHERE chat_id=... AND user_id=...` в SQLite базе `/data/state.db` при остановленном контейнере.
- **Отмена** сворачивает действия.

После действия бот показывает короткое подтверждение и сворачивает клавиатуру. После удаления комментария можно снова открыть «Действия» и включить автоудаление комментариев автора.

## Ограничения MAX API

MAX разрешает ботам читать и удалять комментарии в каналах, но [право `add_remove_members` для ботов в каналах недоступно](https://dev.max.ru/docs-api/methods/POST/chats/-chatId-/members/admins). Поэтому настоящее исключение или блокировка автора в канале через бота пока невозможны.

Эта версия использует [Long Polling](https://dev.max.ru/docs-api/methods/GET/updates), как задумано для простого запуска без публичного сервера. MAX предупреждает, что у polling есть ограничения по скорости и сроку хранения событий и рекомендует webhook для production. При длительном простое часть событий может быть потеряна. Бот хранит курсор после обработки пачки событий и повторяет запрос после ошибки.

Запросы направляются на `https://platform-api2.max.ru`. MAX [требует доверять сертификату Минцифры](https://dev.max.ru/docs-api/changelog-api). Образ уже содержит публичный корневой сертификат `Russian Trusted Root CA` из [официального источника Госуслуг](https://www.gosuslugi.ru/crt) (SHA-256: `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`). Проверка TLS остаётся включённой. При обновлении сертификата в официальном источнике обновите файл в `certs/` и пересоберите образ.

## Проверка без токена

```bash
python3 -m unittest discover -s tests -v
```

Тесты используют поддельный API и не обращаются к MAX. Для проверки реального получения событий и кнопок нужен ваш токен и тестовый канал.
