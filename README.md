# Уведомления о комментариях MAX

Бот для самостоятельного запуска: сообщает администраторам канала MAX о новых комментариях к постам. В уведомлении видно канал, пост, автора и текст комментария. Прямо из уведомления можно перейти к посту, удалить комментарий или включить автоудаление новых комментариев этого автора.

```
💬 Новый комментарий

📢 Канал: Мой канал
📝 Пост: «Начало текста поста…»
👤 Автор: Иван

Текст комментария
```

## Быстрый старт

Нужны [Docker](https://docs.docker.com/get-docker/) с Docker Compose и бот в MAX.

**1. Создайте бота в MAX** и получите его токен и ник (имя без `@`) — по [инструкции MAX для ботов](https://dev.max.ru/docs-api).

**2. Скачайте код и создайте настройки:**

```bash
git clone https://github.com/konstantin-er/max_comment_informer.git
cd max_comment_informer
cp .env.example .env
```

**3. Заполните `.env`:**

```env
BOT_TOKEN=токен-вашего-бота
BOT_USERNAME=ник_бота_без_собаки
```

`BOT_TOKEN` — секретный токен API, никому его не показывайте. `BOT_USERNAME` нужен для ссылки на бота в приветствии.

**4. Запустите:**

```bash
docker compose up -d --build
```

Проверить, что бот работает: `docker compose logs -f bot`. В логе должна появиться строка `Starting MAX comment polling`.

**5. Подключите канал:**

1. Откройте бота в MAX и нажмите «Начать». Каждый администратор, которому нужны уведомления, делает это отдельно.
2. В настройках канала включите комментарии.
3. Добавьте бота в канал и назначьте администратором с правами **читать все сообщения** (`read_all_messages`) и **удалять посты и комментарии** (`delete`).

Готово: при новом комментарии администраторы, начавшие диалог с ботом, получат уведомление.

## Управление

```bash
docker compose logs -f bot   # посмотреть логи
docker compose restart bot   # перезапустить
docker compose down          # остановить (данные сохраняются)
git pull && docker compose up -d --build   # обновить до новой версии
```

Бот сам определяет каналы, где он назначен администратором, список ID каналов в `.env` не нужен. Уведомления получают только действующие администраторы канала, которые начали диалог с ботом. Комментарии самих администраторов и владельца пропускаются: бот не уведомляет о них и не удаляет их. Если удалить бота из канала, уведомления по нему прекратятся.

Состояние (курсор событий, получатели, локальные блокировки) хранится в Docker volume `bot_data`. Не запускайте две копии с одним токеном: они будут конкурировать за поток обновлений.

## Что делают кнопки

- **Перейти** открывает пост. Для приватного канала MAX может не вернуть публичную ссылку на пост; тогда используется ссылка канала, а если её нет — кнопка не показывается.
- **Удалить** удаляет один комментарий через API MAX. Восстановить его нельзя.
- **Блокировать комментарии** удаляет текущий комментарий и заносит автора в локальный список. Следующие комментарии этого автора в данном канале бот удаляет после получения события. Это **не блокировка подписчика в MAX**: до обработки ботом комментарий может быть виден. Список хранится в volume; чтобы убрать запись, можно выполнить `DELETE FROM bans WHERE chat_id=... AND user_id=...` в SQLite базе `/data/state.db` при остановленном контейнере.
- **Отмена** сворачивает действия.

После действия бот показывает короткое подтверждение и сворачивает клавиатуру. После удаления комментария можно снова открыть «Действия» и включить автоудаление комментариев автора.

## Ограничения MAX API

MAX разрешает ботам читать и удалять комментарии в каналах, но [право `add_remove_members` для ботов в каналах недоступно](https://dev.max.ru/docs-api/methods/POST/chats/-chatId-/members/admins). Поэтому настоящее исключение или блокировка автора в канале через бота пока невозможны.

Эта версия использует [Long Polling](https://dev.max.ru/docs-api/methods/GET/updates), как задумано для простого запуска без публичного сервера. MAX предупреждает, что у polling есть ограничения по скорости и сроку хранения событий и рекомендует webhook для production. При длительном простое часть событий может быть потеряна. Бот хранит курсор после обработки пачки событий и повторяет запрос после ошибки.

Запросы направляются на `https://platform-api2.max.ru`. MAX [требует доверять сертификату Минцифры](https://dev.max.ru/docs-api/changelog-api). Образ уже содержит публичный корневой сертификат `Russian Trusted Root CA` из [официального источника Госуслуг](https://www.gosuslugi.ru/crt) (SHA-256: `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`). Проверка TLS остаётся включённой. При обновлении сертификата в официальном источнике обновите файл в `certs/` и пересоберите образ.

## Проверка без токена

```bash
python3 -m unittest discover -s tests -v
```

Тесты используют поддельный API и не обращаются к MAX. Для проверки реального получения событий и кнопок нужен ваш токен и тестовый канал.
